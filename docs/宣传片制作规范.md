# 宣传片制作规范

> **给 AI 的提示词**。本文件记录了一套**已验收通过**的宣传片制作方法（来源：[AutoSync](https://github.com/szkele1145/AutoSync) 项目的宣传片，用户验收时原话是「我非常非常非常满意」）。
>
> **请严格按本规范执行**，尤其是「第五章 禁止事项」—— 那些都是实际踩过、被用户明确否掉的坑。

---

## 一、交付物

必须产出三样，缺一不可：

| 交付物 | 说明 |
|---|---|
| **1. 单文件 HTML** | 纯 HTML+CSS+JS，**双击用浏览器打开就能完整播放**（含配音） |
| **2. mp4 视频** | 1920×1080 / 30fps / H.264 / yuv420p / AAC 音轨 |
| **3. 封面图** | 1146×717（B 站标准），JPG < 5MB |

**「能预览」是硬指标** —— HTML 必须零依赖直接打开。不要搞需要构建、需要起服务器、需要额外装东西的方案。

---

## 二、技术方案（照做，不要自创）

### 2.1 播放器：单文件 HTML + **JS 时间轴驱动**

```
AutoSync-宣传片.html          ← 单文件，浏览器直接打开
├── 分镜脚本 SCRIPT[]         ← 数组，每个元素 = 一个镜头
│     { d: 2400,              ← 时长(ms)
│       sub: '字幕/配音稿',
│       html: `...画面HTML...` }
├── 播放引擎                  ← requestAnimationFrame 按时间推进
└── seekTo(ms)                ← 关键：把时间轴定位到指定毫秒并暂停
```

**核心要求：所有动画必须由 JS 时间轴函数驱动，禁止使用 CSS `@keyframes`。**

**为什么**：录制时是**逐帧截图**，每一帧都要能精确定位到某个时间点的画面状态。CSS 动画由浏览器自己走时钟，截图时无法控制，会拍到"动画走到一半"的随机状态。

**确定性验证（必须通过）**：
```js
// 同一毫秒渲染两次，DOM 必须完全一致
seekTo(5000); const a = stage.innerHTML;
seekTo(5000); const b = stage.innerHTML;
console.assert(a === b, '帧内容不一致！');
```

### 2.2 配音：**edge-tts**（不要用浏览器 TTS）

```bash
pip install edge-tts

# 中文语音（推荐）
edge-tts --voice zh-CN-YunxiNeural   --rate=+15% --text "..." --write-media 01.mp3   # 男声，年轻自然
edge-tts --voice zh-CN-XiaoxiaoNeural --rate=+15% --text "..." --write-media 01.mp3   # 女声

# 语速 +15% 起步（用户嫌默认慢），±20% 之间微调
#   ⚠️ 2026-10-06 修正：用户后来明确「配音语速不能变」——改用 edge-tts **默认语速**
#   （不要传 --rate），上面这句 +15% 作废。语速变慢后每段音频更长，镜头时长要按
#   音频实际时长来定，必要时把文案改短，避免音频溢出画面。
# 文件命名 = 镜头序号（01.mp3、02.mp3…），字幕为空的镜头跳过
```

**HTML 里播放 mp3**，同时保留 `V` 键开关配音。**文件缺失时必须静默降级**（不报错、画面继续）。

### 2.3 自动录制：Puppeteer + ffmpeg（不要手动录屏）

```bash
npm i puppeteer-core ffmpeg-static    # puppeteer-core 用系统 Edge，不下载 Chromium
```

**流程**：

```
1. 无头启动 Edge，视口 1920×1080
2. 打开 HTML，注入 CSS 隐藏所有 UI 控件（#hud 之类）
3. 逐帧截图：for (i = 0; i < totalFrames; i++) { seekTo(i * 1000/30); screenshot(); }
     总帧数 = 时长(秒) × 30
4. ffmpeg 合成：H.264 / yuv420p / 30fps
5. 混入配音音轨（多段 mp3 按时间轴对齐）
```

**耗时预期**：单帧约 150~200ms，3300 帧 ≈ **8~12 分钟**。（这是**录制耗时**，不是视频时长，别搞混）

**ffmpeg 装不上时**：直连 GitHub 常超时，用镜像：
```powershell
cd node_modules\ffmpeg-static
$env:FFMPEG_BINARIES_URL="https://registry.npmmirror.com/-/binary/ffmpeg-static"
node install.js
```

### 2.4 音轨对齐（容易漏）

edge-tts 生成的 mp3 **自带 0.7~1.0 秒尾部静音**。如果音轨比视频短，用 `apad` 补齐：

```bash
ffmpeg ... -af "apad" -shortest ...
```

**验收**：`ffprobe` 读出音轨长度与视频长度**差 < 0.1 秒**。

## 三、视觉风格规范

### 3.1 配色（深色科技风）

> ⚠️ 2026-10-06 修正：项目所有者要求「**文档站什么风格宣传片就什么风格，不要一模一样**」。
> 因此**配色以本项目的文档站 `docs/assets/site.css` 为准**（霓虹青绿主调），
> 不再使用下面这套 One Dark（青 `#56b6c2` + 紫 `#c678dd`）。下面是参考片的原始配色，
> 仅作历史记录保留：
>
> 文档站当前值（**应用这一套**）：
> ```css
> --bg:#0b0f12; --bg-2:#11181d; --panel:#0f161b; --panel-2:#131c22;
> --line:rgba(125,180,165,.16); --line-accent:rgba(61,220,151,.35);
> --accent:#3ddc97; --accent-2:#38bdf8;
> --radius:14px; --radius-sm:9px;
> /* 标题渐变 linear-gradient(100deg,#eafff7 0%,var(--accent) 42%,var(--accent-2) 100%) */
> ```
> 「不要一模一样」= 统一**设计语言**（色彩/调性/字体/圆角），但**不要照搬文档站的页面结构**
> （hero 区、卡片网格、文档表格、左侧 TOC、页脚栏）；宣传片要用**视频语言**表现
> （镜头与交叉溶解、JS 时间轴动效、终端窗口、逐行打字、底部字幕）。

```css
:root{
  --bg:     #0a0e14;   /* 背景：近黑蓝 */
  --panel:  #10151f;   /* 面板 */
  --line:   #1e2733;   /* 描边 */
  --txt:    #dfe6f0;   /* 主文字 */
  --dim:    #78839a;   /* 次要文字 */

  --cyan:   #56b6c2;   /* 主强调色 */
  --blue:   #61afef;
  --purple: #c678dd;   /* 次强调色 */
  --green:  #98c379;   /* 成功/正向 */
  --yellow: #e5c07b;   /* 警告 */
  --red:    #e06c75;   /* 错误/负向 */
}
```

**标题渐变**：`linear-gradient(100deg, var(--cyan), var(--blue) 42%, var(--purple) 80%)` + `background-clip: text`

### 3.2 字体

```css
font-family: "Cascadia Code", "JetBrains Mono", Consolas, "Microsoft YaHei", monospace;
```

**等宽字体**是技术类视频的标配，能让终端/日志/代码看起来对。

### 3.3 背景（三个层次叠加）

1. **径向渐变光晕** —— 左上青色、右下紫色，`opacity` 0.10~0.14
2. **透视网格** —— `transform: perspective(680px) rotateX(60deg)`，缓慢滚动，用 `mask-image` 做边缘淡出
3. **（可选）浮点/星点** —— 纯 CSS 小圆点，`animation-delay` 错开制造随机感

### 3.4 字幕

底部居中大字幕，**必须加**：

```css
#sub{
  position: fixed; left: 50%; bottom: 6vh; transform: translateX(-50%);
  max-width: min(1180px, 90vw);
  background: rgba(6,9,13,.80);        /* 半透明黑底，保证任何画面上都可读 */
  backdrop-filter: blur(7px);
  border: 1px solid rgba(86,182,194,.28);
  border-radius: 9px;
  font-size: clamp(15px, 2.2vw, 30px); /* 字号要够大 */
  font-weight: 600;
  text-shadow: 0 2px 10px rgba(0,0,0,.85);
}
```

**排版陷阱**：长字幕会挤成两行、留下一个孤字。**写完每句字幕都要检查天然宽度**，必要时改措辞（改短比改容器安全 —— 改容器会影响其他镜头）。

## 四、叙事与节奏

### 4.1 镜头要**碎**

**平均 2~3 秒一个镜头**（75~110 秒 → 25~35 个镜头）。

长镜头是完播率杀手。要让每 2~3 秒就有新信息或新画面。

> ⚠️ 2026-10-06 修正：用户另外要求「**结构紧凑一点**」——镜头时长按 **2 秒左右**为主
> （个别信息量大的最多 3 秒），**总时长控制在 75~90 秒**，不要往 110 秒靠。
> 转场交叉溶解仍保持 0.4 秒（别缩短，短了会显硬）。

### 4.2 推荐结构（6 幕）

| 幕 | 时长占比 | 内容 |
|---|---|---|
| 1. 开场 | 8% | 项目名 + 一句话定位 + 标签 |
| 2. 痛点 | 20% | 现状有多糟（**逐条堆叠出现**，不要一次全放） |
| 3. 方案/演示 | 25% | 终端/界面演示，逐行打字 |
| 4. 技术亮点 | 20% | 对比卡片（旧方案 ✘ vs 新方案 ✔） |
| 5. 数据 | 18% | 数字滚动 + 数据条生长 + 对比表 |
| 6. 收尾 | 9% | 仓库地址 + 致谢 + 制作标识 |

### 4.3 动效清单（这些是**加分项**，做过验收）

| 动效 | 说明 |
|---|---|
| **数字滚动 count-up** | 关键数字从 0 滚到目标值，末尾带弹性 |
| **打字机** | 终端逐**字符**打出（不是整行出现），光标跟随 |
| **光带扫过** | 标题/关键文字上有渐变高光横向扫过（`background-position` 动画） |
| **下划线绘制** | 标题下的横线 `scaleX(0→1)` 画出来 |
| **高亮框移动** | 列表项之间的高亮色块平移（色块动，文字不动） |
| **数据条生长 + 数字同步** | 条子变长的同时右侧数字跳动 |
| **环形进度 / 折线描边 / 环形图扇出** | SVG `stroke-dasharray` 描出来 |
| **脉冲波纹** | 3 层同心圆从中心扩散（只做 `scale` + `opacity`） |
| **呼吸光晕** | `text-shadow` 强弱周期变化 |
| **卡片依次点亮** | 不是同时出现，逐个 opacity + 边框发光 |
| **扫描线** | 终端/数据面板上细横线下移（CRT 质感） |
| **色相缓慢偏移** | 整屏 `filter: hue-rotate ±9°`，周期 17s |
| **错误抖动** | 出现"错误/拦截"时窗口轻微 `scale` 抖动 |

## 五、⛔ 禁止事项（都是被用户明确否掉的）

### 5.1 **禁止任何位移入场**

> 用户原话：「为什么每次都不是流畅的动画，而是**从下面拉上去**，这很诡异」

- ❌ **不要** `translateY(20px) → 0`
- ❌ **不要** `translateX(-26px) → 0`
- ❌ **不要** 任何"元素从画面外滑进来"
- ✅ **要** 纯 `opacity` 淡入，最多加极轻微 `scale(1.015) → 1`

**唯一允许位移的**：背景网格滚动、高亮色块在列表项间移动（色块动，文字不动）。

### 5.2 **禁止镜头硬切**

`stage.innerHTML = ...` 直接替换会**闪一下**。

✅ **要** 交叉溶解：旧镜头淡出与新镜头淡入**重叠约 0.4 秒**。

### 5.3 **禁止使用浏览器 TTS**

> 用户原话：「这个讲述人讲的**太慢了**，然后还**很人机**」

`speechSynthesis` API 的音质和语速都不可接受。**必须用 edge-tts 预生成 mp3**。

### 5.4 **禁止录制时出现 UI 控件**

> 用户原话：「这个录制会录到**这个角落的那些按钮**」

**不要靠人工按快捷键隐藏** —— 录制脚本里用 `page.addStyleTag` **强制注入**：

```js
await page.addStyleTag({ content: '#hud{display:none !important} ::-webkit-scrollbar{display:none}' });
```

### 5.5 **禁止只给"能跑"但不给"能看"的产物**

用户明确要求**先看效果再录制**。所以要**分两阶段**交付：

```
阶段一：单文件 HTML + 配音 → 让用户在浏览器里看/听 → 确认
阶段二：确认后再录制 mp4
```

**不要在用户确认前就开始录制**（要 8~12 分钟，脚本或配音不满意就白做了）。

### 5.6 其它已知坑

| 坑 | 现象 | 解决 |
|---|---|---|
| **`DefaultCaret` 自动滚动** | 日志区里用户往上翻，会被新内容强行拽到底 | 禁掉 caret 的 `adjustVisibility`，自己接管滚动；把 ↑↓/PageUp/PageDown 显式绑到滚动条 |
| **中文字幕挤成两行** | 末尾留一个孤字 | 检查天然宽度，改短措辞（别改容器，会波及其他镜头） |
| **音轨比视频短** | 结尾静音 | ffmpeg 加 `apad` |
| **`-javaagent` 中文路径** | 参数到 `premain` 时路径损坏 | 只传纯 ASCII 文件名 |
| **探针往 EDT 投任务** | JVM 不退出 | 采样线程直接读组件（`DefaultBoundedRangeModel` 读方法线程安全） |

## 六、验收标准

录制完成后**必须自检并汇报**：

| 项 | 要求 |
|---|---|
| 分辨率 | 1920×1080 |
| 帧率 | 30 fps（视频流实际帧数 = 时长 × 30） |
| 编码 | H.264 High / **yuv420p**（B 站直传要求） |
| 音轨 | AAC 48kHz stereo，**非静音**（`volumedetect` 看 `mean_volume`，峰值贴近 0dB 但不削波） |
| 时长偏差 | 与设计时长差 **< 0.5 秒** |
| **音轨对齐** | 音轨长度与视频长度差 **< 0.1 秒** |
| **无黑屏** | `blackdetect` 检查，不应有 > 0.5s 的黑段 |
| **无 UI 控件** | 抽查多个时间点，画面里**不能有按钮、进度条、鼠标** |
| **关键帧抽查** | 导出开头/中间/结尾的截图，确认渲染正确、文字无裁切 |
